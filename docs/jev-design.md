# Jev 連携の設計

重要度判定に [Jev](https://docs.typesafe.ai/)(TypeSafe AI の判断特化モデル)を使う。
Jev は文章を生成せず、**型付きの答え(Score / Choice / Noul)と確信度**を返す。
そのため「重要度そのものを聞く」のではなく、**観点ごとに小さく判定させ、重要度はコード側で決める**設計にしている。

## 全体の流れ

```
記事(title / summary / source / published)
   │  記事 1 件 = API 1 回(state=記事、questions=4 観点を並列に質問)
   ▼
Jev ── impact / urgency / novelty (Score) + noise (Noul) + 各 confidence
   ▼
コードで合成: Σ(重み×正規化スコア) × (1 − 0.5×noise)   … カテゴリ別の重み
   ▼
合成スコア 0〜1 ──閾値──▶ 重要度 1〜5(最重要=5 / 重要=4 / 注目=3 / 通常=2,1)
   ▼
カテゴリ内を「合成スコア(Jev ベース)→ 新しさ」の順で並べる(Lv は表示用の区分)
```

## 質問(観点)

| ID | 種類 | 内容 | 段階 |
|----|------|------|------|
| `impact` | Score | 影響範囲(個人の話題 → 業界・社会インフラ) | 0〜3 |
| `urgency` | Score | 緊急性(読み物 → 今すぐ対応) | 0〜3 |
| `novelty` | Score | 新規性(再整理 → 一次情報・速報) | 0〜2 |
| `noise` | Noul | 広告・PR・セール・ランキング・雑談か | 確率 0〜1 |

- 1 質問 1 観点。各レベルは「程度」ではなく**具体的な状況**で書く(Jev の推奨)
- 定義は `jev_client.py` の `QUESTIONS`

## 合成ルール

- 各 Score を最大レベルで割って 0〜1 に正規化
- カテゴリ別の重み(`WEIGHTS`)

  | カテゴリ | impact | urgency | novelty |
  |----------|--------|---------|---------|
  | 既定 | 0.40 | 0.35 | 0.25 |
  | security | 0.30 | **0.55** | 0.15 |
  | general | 0.45 | 0.15 | **0.40** |

- `noise` が高いほど合成スコアを下げる(最大 −50%)
- 閾値(`THRESHOLDS`): 0.70↑=5 / 0.50↑=4 / 0.32↑=3 / 0.15↑=2 / それ未満=1
  - **初期値。実データで分布を見て調整する**(最重要が多すぎ・少なすぎないか)

## 確信度と安全側の挙動

- 平均 confidence が 0.4 未満 → 合成スコアとキーワード判定を 50:50 で平均(`jev+keyword`)
- 401/403 → 以降の呼び出しを止め、全件キーワード判定へ(無駄な呼び出しと失敗ログを防ぐ)
- 429/529 → `Retry-After` または指数バックオフで最大 3 回
- その他の失敗 → その記事だけキーワード判定
- `JEV_API_KEY` 未設定 → 全件キーワード判定(ローカル実行・フォーク先でも動く)

## 人気記事(Qiita / Zenn)の「アツさ」

`feeds.yml` のカテゴリに `mode: heat`(と `sort: likes`)を付けると、そのカテゴリは重要度ではなく **アツさ**(面白さ・共感の広がり)で判定する。

- 並び順は **いいね数の多い順**(Jev のスコアではない)。いいね数は RSS に無いため、`likes: zenn|qiita` を付けたフィードの記事だけ各サイトの公開APIから取得する
- Jev の質問は別セット: `curiosity`(面白さ 0〜3)/ `learning`(学び 0〜2)/ `appeal`(共感の広がり 0〜3)/ `noise`(Noul)
- 重み: curiosity 0.45 / appeal 0.30 / learning 0.25(`HEAT_WEIGHTS`)。合成後の Lv 区分は重要度と同じ閾値
- 表示は `Lv` ではなく `アツさ` + 5段の棒。ホバーで内訳(面白さ・共感の広がり・学び・宣伝度)と確度
- Jev が使えない場合の簡易判定は、いいね数(100↑=5 / 50↑=4 / 20↑=3 / それ未満=2)
- 「注目ニュース」と「Lv5 N件・Lv4 M件」の集計には含めない

## コスト・速度

- 1 記事 ≒ 400〜600 入力トークン。450 件/日でも約 $0.01/日(入力 $0.042/100万トークン、出力は無料)
- 並列 6。レート上限(1,200 req/分)に対して余裕あり
- **キャッシュ**: 判定結果を `data/jev-cache.json`(gh-pages 上)に URL 単位で保存し、翌日以降は再判定しない
  - 質問・重みを変えたら `CACHE_VERSION` を上げる(全件再判定)
  - キーワード判定になった記事は保存しない(次回 Jev で再挑戦)

## 設定

| 名前 | 種別 | 内容 |
|------|------|------|
| `JEV_API_KEY` | Secret(必須) | Jev API キー(https://typesafe.ai で発行) |
| `JEV_API_URL` | 環境変数(任意) | 既定 `https://api.typesafe.ai/v1/systemone` |
| `JEV_MODEL` | 環境変数(任意) | 既定 `jev-latest` |

## 表示

- 重要レベル: 各記事に `Lv1`〜`Lv5`(5段の棒)を表示。ホバーで内訳(影響範囲・緊急性・新規性・宣伝度)と Jev の確度を確認できる
- Lv は合成スコアを閾値で区切った表示用の区分。並び順は区分ではなく合成スコアそのもの(区分の境目で順序が崩れない)
- 「注目ニュース」は重要度 4 以上から上位 5 件

## 今後の拡張案

- 閾値のキャリブレーション(実データで最重要の割合を 3〜5% 程度に)
- 読者の関心(利用技術)を Noul で判定し、パーソナライズ用の観点を追加
- 重複トピック(同じニュースを複数サイトが報道)の検出・グルーピング
