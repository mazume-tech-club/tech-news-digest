# 重要な理由ラベル・同じ話題の束ね・既読(Cookie)の設計

実装は `curation.py`(外部通信なし)と `render.py`。

## 重要な理由ラベル

一覧の 1 段目に、Lv の横へ **1〜2 個のラベル** を常に表示する(マウスオーバーに頼らない。スマホでも見える)。
Lv3 以上の記事には必ず 1 つ以上付く。

| ラベル | 色 | 付く条件 |
|--------|----|----------|
| 情報漏えい発生 | 赤 | タイトル・概要に「情報漏えい / 流出 / 不正アクセス / data breach」など |
| 悪用確認済み | 赤 | 「悪用を確認 / ゼロデイ / actively exploited / ランサムウェア」など |
| 今すぐ対応 | 赤 | Jev の `urgency` が最大(今すぐ対応が必要) |
| サービス障害 | 茶 | 「大規模障害 / 障害発生 / outage」など |
| サービス終了予告 | 茶 | 「サービス終了 / サポート終了 / 廃止 / deprecat / EOL」など |
| 料金改定 | 茶 | 「値上げ / 価格改定 / 料金改定」など |
| 規約変更 | 茶 | 「利用規約 / 規約変更 / terms of service」など |
| 脆弱性 | 茶 | 「脆弱性 / CVE-」など(悪用確認済み・今すぐ対応があるときは省く) |
| 一般提供開始 | 茶 | 「一般提供 / 正式版 / GA / generally available」など |
| 影響:広い | 茶 | Jev の `impact` が 2/3 以上 |
| 新情報 | 灰 | Jev の `novelty` が最大(一次情報・速報) |
| 注目 | 灰 | 上のどれにも当たらない Lv3 以上(Jev 未使用時など) |
| 人気 / 試したくなる / 共感が広い | 灰 | 人気記事(アツさ)。いいね 50 以上 / `curiosity`・`appeal` が 2/3 以上 |

- 並びは 赤 → 茶 → 灰。同じ色ならルールの順
- Jev の質問は増やしていない(`CACHE_VERSION` は据え置き)。キーワードと既存の内訳(impact / urgency / novelty)の組み合わせで決める
- 詳細を開くと「重要な理由」の 1 文(先頭ラベルに対応する定型文。2 つ目が「影響:広い」なら補足)。
  キーワード判定の記事には「(キーワードによる簡易判定)」を付ける。フォロー一致は画面側で「フォロー中の『X』に一致。」を前置きする
- ページの変化は種類ラベル(障害 / 料金 / 規約 / 発表)を付け、理由の文は種類ごとの定型文

## 同じ話題の束ね

同じ出来事を報じた記事を 1 行にまとめ、「同じ話題 N件」と表示する。詳細に関連記事の一覧を出す。

- 判定(`same_topic`): 公開時刻が 72 時間以内で、
  - タイトルの文字 bigram の Jaccard 係数 ≧ 0.5、または
  - 一般的でない固有名詞(英単語・カタカナ語・漢字 3 字以上・かぎ括弧内)が 2 つ以上一致 かつ Jaccard ≧ 0.25、または
  - 4 文字以上の固有名詞が 1 つ一致 かつ Jaccard ≧ 0.3
- 同じソースの記事同士は束ねない(連載・続報を潰さない)。日付だけのタイトル(リリースノート)は束ねない
- 「Claude / Google / AWS / エージェント」など頻出語(`_GENERIC`)だけの一致では束ねない
- 束ねた中でスコア最上位が代表。代表を開く(既読にする)と関連記事も既読になる
- 2026-11-27 の公開データ(462 件)で 13 組。誤って束ねたのは「Terraform のリモートステート」の 2 記事(同じ話題の別記事)程度

## 既読・設定の Cookie

| Cookie | 内容 |
|--------|------|
| `tnd_r` | 既読の記事ID。`日番号:id.id.id~日番号:id…`。直近 7 日分だけ保持し、3,800 文字を超えたら古い日から捨てる |
| `tnd_w` | 「すべて既読にする」を押した時点のページ生成時刻(UNIX 秒)。これ以前に **初めて収集した** 記事は既読 |
| `tnd_follow` | フォロー中のキーワード(JSON 配列) |
| `tnd_mute_src` / `tnd_mute_kw` | 見ないソース / キーワード(JSON 配列) |
| `tnd_theme` | `light` / `dark` |

- 属性: `Path=/tech-news-digest/; SameSite=Lax; Secure`(https のとき)、有効期限 400 日
- 記事ID = URL の SHA-1 の先頭 7 文字(`curation.article_id`)。1 件 8 バイトなので、1 日 65 件 × 7 日でも上限(3,800 文字)に収まる。それ以上読む人は「すべて既読」(`tnd_w`)で一括管理される
- 「初めて収集した時刻」は `data/first-seen.json`(gh-pages)に記事ID単位で保存する。公開日時の古い記事を後から収集しても、
  「すべて既読」後の新着として扱える
- **フォローは「話題」単位**: 記事ごとの固有名詞(例:「マイナアプリ」「赤ちゃんファースト」)ではなく、毎日繰り返し出てくる
  技術・製品・テーマ(`curation.TOPICS`。例: AWS / Google Cloud / Claude / マイナンバー / 脆弱性 / 情報漏えい)をフォローボタンに出す。
  話題は別名でも一致する(「マイナンバー」は「マイナアプリ」「マイナ保険証」にも、「Google Cloud」は「Cloud Run」「BigQuery」にも)。
  タイトル・概要・ソース名から判定し、どれにも当たらない記事だけ代表キーワードを出す。話題は PR で `TOPICS` に追加できる
- 設定(PC の表示設定・スマホの設定タブ)から、任意のキーワードを直接フォローできる
- 「見ない」は誤って広く消さないよう、記事ごとの代表キーワード(固有名詞)のまま
- キーワードのミュート・フォローは、タイトル(日本語訳・原題)とソース名に部分一致(大文字小文字を区別しない)
- 既読にした記事も見返せる: PC は「すべて」、スマホは新着タブの「既読も表示」(読み終えた画面の「読んだ記事も表示する」)。注目・フォロータブは既読も含めて表示
- JS が無効でも全記事が読める(既読・設定・フォロー欄は JS による追加機能)
